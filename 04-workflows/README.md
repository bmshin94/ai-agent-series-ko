# 4편: 에이전트가 정답이 아닐 때 — 워크플로 패턴 5가지

1편부터 만든 점심 에이전트를 **루프 없이** 다시 짜 봤어요.
**워크플로는 다음 단계를 코드가 정하고, 에이전트는 모델이 정해요.** 둘 다 LLM을 쓰지만 핸들을 잡는 쪽이 달라요.
같은 문제를 두 방식으로 5번씩 돌려서 비교하고, 워크플로 패턴 5가지를 점심 예제로 하나씩 만들어 봤어요.

| 파일 | 내용 |
|---|---|
| `lunch_tools.py` | 1~3편 도구(식당 목록·지갑·계산기·걸어서 몇 분) + 메뉴 종류 도구 |
| `lunch_agent.py` | 에이전트 방식: 1~3편 루프 그대로, 모델 호출 수·토큰을 세도록만 바꿈 |
| `lunch_workflow.py` | 워크플로 방식: 조회·조건 검사는 그냥 파이썬, 모델은 추천 문구 쓸 때 한 번만 |
| `compare.py` | 두 방식을 같은 질문으로 5번씩 — 정답 횟수·모델 호출 수·토큰·시간 |
| `open_request.py` | 요청 모양이 바뀌면? (혼자·걸어서 8분 안·국물에 밥) 짜 둔 워크플로 vs 에이전트 |
| `patterns.py` | 패턴 5가지: `chain` · `route` · `parallel` · `orchestrator` · `evaluator` |
| `실행기록_*.txt` | 2026-11-12에 실제로 실행한 결과 (모델: gemini-flash-lite-latest) |

## 실행

```bash
cd 04-workflows
python lunch_workflow.py          # 워크플로 한 번
python lunch_agent.py             # 에이전트 한 번
python compare.py                 # 5번씩 비교 (무료 한도 때문에 실행 사이 20초씩 쉬어요)
python open_request.py            # 바뀐 요청
python patterns.py chain          # route / parallel / orchestrator / evaluator 도 같은 방식
```

준비: `pip install google-genai`, 환경변수 `GOOGLE_API_KEY`에 Gemini API 키

> ⚠️ 무료 한도는 모델마다 달라요. 제가 실행할 때(2026-11) Flash Lite 모델은 무료로 **1분에 15번**까지였어요. 패턴은 하나씩 나눠서 실행하세요.
> 모델의 답은 실행할 때마다 조금씩 달라요. 결과가 영상과 똑같지 않아도 이상한 게 아니에요.

## 실험 결과 (실행 기록 참고)

| 실험 | 결과 |
|---|---|
| 같은 점심 문제, 방식별 5번 | 정답 둘 다 5/5 · 모델 호출 평균 3.6번 vs 1번 · 토큰 평균 2,021개 vs 114개 · 평균 9.5초 vs 2.6초 |
| 바뀐 요청 (혼자·8분 안·국물에 밥) | 워크플로는 짜 둔 길대로 분식나라(오답) / 에이전트는 메뉴 도구를 써서 국밥집 |
| 체이닝 | 추천 문구 → 관문(식당 이름 있나?) → 한 줄 요약 |
| 라우팅 | 가까운 곳 → 제육볶음집 / 특별한 날 → 라멘집 / 아끼기 → 김밥천국 |
| 병렬화 | 식당 소개 3개: 하나씩 5.6초 / 동시에 3.9초 |
| 오케스트레이터-워커 | 국밥집을 골랐지만 데이터에 없는 '맑은 육수'를 지어냄 — 유연한 만큼 예측하기 어려움 |
| 평가자-최적화 | 1번째 글 탈락(버전 3개·과장 표현) → 2번째 글 통과 |

## 꼭 기억할 세 가지
1. 워크플로는 코드가, 에이전트는 모델이 다음 단계를 정한다
2. 순서를 미리 적을 수 있으면 워크플로가 더 빠르고 싸다
3. 단계를 예측할 수 없을 때만 에이전트에게 핸들을 넘긴다
